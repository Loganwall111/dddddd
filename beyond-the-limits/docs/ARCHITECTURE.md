# Architecture

Beyond the Limits is built on one rule: **the server owns the world, the client owns only how it is
seen.** Everything else follows from that, and it is why the mod can put a procedural sky, a lensing
pass and a screen-space glitch over the game without any of it leaking into the simulation.

```
                    ┌──────────────────────────────────────────┐
   the world  ────▶ │  core/            the simulation         │
                    │  BtlState, BtlEngine, 21 engines         │
                    └───────────────┬──────────────────────────┘
                                    │ BtlNetworking (S2C)
                    ┌───────────────▼──────────────────────────┐
   the player ─────▶ │  client/          the presentation       │
                    │  ClientState, render, hud, screen, {particle,shader} │
                    └──────────────────────────────────────────┘
```

## Layers

| Layer | Package | Responsibility |
|---|---|---|
| Simulation | `core/` | `BtlState` (the world's memory), `BtlEngine` (the tick dispatcher), `BtlConfig` (every tunable number), `BtlMemory` (per-player history) |
| Engines | `core/engine/` | 21 independent systems, one per anomaly plus supporting machinery. Each exposes `tick(...)`-shaped entry points and never reaches into another engine's state. |
| Content | `block/`, `item/`, `entity/` | Blocks and items with behaviour; 19 entities from the Smiler to the Black Sun |
| Registries | `registry/` | The only place anything is registered: blocks, items, entities, particles, sounds, effects, tags, block entities, dimensions, chunk generators |
| Data | `src/main/resources/data/` | Dimensions, dimension types, biomes, loot tables and tags — generated by `tools/gen_datapack.py` |
| World | `world/` | Structures, the seamless portal, the City generator, the world event wiring, the sky events |
| Commands | `command/` | `/beyondthelimits`, `/btl`, and vanilla `/teleport backrooms` |
| Mixins | `mixin/` | Three server-side (shutdown save, world tick, `/teleport backrooms`) and three client-side (sky takeover, fog, `renderSky` access) |
| Client | `client/` | `ClientState`, GLSL programs, sky renderer, rift renderer, post effects, HUD, the journal, the Code Verse terminal, particles, entity renderers, keybinds |

## The simulation

`BtlState` is a single NBT-serialised object holding the world's memory: reality integrity, world
collision, sky cracking, black sun stage, storm state, the lost civilization's stage, bleeding,
moving chunk position, the signal, evolution stages per mob family, per-player dementia and
dimensional gravity debt, every anomalous position ever seen, every memory recorded, sleeps counted,
the guide's state, the City's state and the rift seed. It is saved with the world and read by every
engine.

`BtlEngine` is the dispatcher. Every server tick it runs the engines in a fixed order with a work
budget (`BtlConfig.WORK_BUDGET`), which is what keeps a mod that simulates twenty anomalies from
costing twenty anomalies' worth of tick time. Order matters and is deliberate: the world is measured
first, then damaged, then the damage is presented.

Engines never call each other's internals. Where two systems must interact — a storm triggering
rift lightning, a mob evolving from a kill — the interaction is a public method on the engine that
owns the state, or an entry in `BtlState`.

## The presentation

`ClientState` mirrors the numbers the server sends: reality, dementia, gravity debt, sky event,
and the current screen effect. It is a pure function of the last packet received, which means the
renderer and the HUD can be written without knowing anything about the simulation.

Three things happen per frame:

1. **The sky** (`SkyRenderer` + `sky_warp.fsh`) — if an event is running, or the dimension is
   sky-only, vanilla's sky is skipped and the mod's sky is drawn instead. Vanilla's own sky remains
   available through `BtlSkyRenderer`, which is what makes "the sky is fake" possible: the cracks
   are drawn *over the real sky*, so there is never a frame with no sky at all.
2. **Rifts** (`RiftRenderer` + `rift.fsh`) — every rift within 128 blocks is drawn as concentric
   rings with a torn rim and a halo. No geometry is ever a block: a rift is light.
3. **The overlay** (`PostEffects` + `screen_glitch.fsh` / `scan.fsh`) — drawn last, over everything.

### Why an overlay and not a post-process

A true post-process pass needs the world framebuffer, and a mod must never assume it owns that:
Iris, Sodium and other mods all take turns owning the pipeline. So instead of distorting the frame,
the glitch pass lays down the *evidence* of distortion — tear bands, chromatic ghosting, scanline
wash, darkening, per-mode shapes. It reads the same way, costs a fraction as much, and cannot break
another mod's rendering.

## GLSL

Four core shaders, registered through Fabric's `CoreShaderRegistrationCallback` so they work in any
modpack without a resource pack:

| Program | Source | What it does |
|---|---|---|
| `beyondthelimits:core/rift` | `rift.fsh` | The tear: polar-space noise, per-variant palettes, a rim that dissolves so there is never a quad edge |
| `beyondthelimits:core/sky_warp` | `sky_warp.fsh` | The whole sky, procedural, with eleven modes and gravitational lensing |
| `beyondthelimits:core/screen_glitch` | `screen_glitch.fsh` | Ten interference modes plus the always-on reality damage |
| `beyondthelimits:core/scan` | `scan.fsh` | The scanner's grid and sweep, and the Void Lens's colder version of it |

The shaders are self-contained: no `#moj_import`, no extensions, no framebuffer reads. Every uniform
is declared with a default in the program's JSON, so a shader that fails to load degrades to
"effect missing" rather than "game broken".

## Mixins

| Mixin | Side | Why |
|---|---|---|
| `MinecraftServerMixin` | server | Saves `BtlState` on shutdown |
| `ServerWorldMixin` | server | `tickChunk` → `SkyEvents`, so sky shards and cracks advance per chunk |
| `TeleportCommandMixin` | server | Grafts `/teleport backrooms` onto vanilla's teleport command |
| `WorldRendererMixin` | client | Takes over `renderSky` while an event runs, and draws the overlay after vanilla's sky |
| `BackgroundRendererMixin` | client | The fog director: Foglands white-out, Codescape haze, Backrooms warmth, reality damage |
| `SkyRenderingMixinAccess` | client | An `@Invoker` so the mod can ask vanilla to draw its own sky on demand |

Every mixin is written to fail safe: `require = 0` where a version difference could remove the
target, and no mixin touches state it does not own.

## Data flow of one event

A storm makes a good example because it touches every layer:

```
StormEngine.beginStorm()        server: writes to BtlState, stamps terrain, spawns
        │
        ├─▶ BtlNetworking.sendSkyState()     packet: sky event + intensity + duration
        │            │
        │            ▼
        │      ClientState.setSky()           client: the number the renderer reads
        │            │
        │            ▼
        │      SkyRenderer.shouldReplaceSky() → sky_warp.fsh, Mode = 2 (storm)
        │
        └─▶ BtlNetworking.sendScreenEffect()  packet: EFFECT_STORM
                     │
                     ▼
              PostEffects.render() → screen_glitch.fsh, Mode = 3
```

Nothing is duplicated: the storm exists once, on the server, and the client draws two effects from
two numbers.
